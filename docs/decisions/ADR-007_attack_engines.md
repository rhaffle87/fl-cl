# ADR-007: Dual-Engine Threat Generation Architecture (Kali Binaries vs. Native Python)

## Status
Accepted

## Date
2026-08-28

## Context
In the `fl-cl` intrusion detection testbed, a dedicated Traffic Generator node (VM 400, Kali Linux at `10.10.140.10`) simulates 4 threat attack classes (SSH Brute Force, Slowloris DoS, DNS Exfiltration, and Botnet C2 Beaconing) alongside benign background traffic.

Previously, traffic generation was split ad-hoc between a hardcoded `hydra` subprocess call and pure Python socket scripts. This raised questions regarding:
1. **Adversary Realism**: Does synthetic Python socket traffic sufficiently represent real offensive tooling in production and enterprise environments?
2. **Reproducibility & Portability**: Can the testbed execute on minimalist environments without pre-installed Kali Linux penetration testing suites?
3. **Flow Metric Consistency**: How do alternative tools impact NFStream flow feature extraction and supervised labeling integrity in `assign_labels_vectorized`?

## Considered Options
1. **Pure Python Exclusively**: Remove all external system binary calls (`hydra`, etc.) and use only Python standard library (`socket`, `urllib`) and PyPI packages (`slowloris`).
2. **Kali Security Binaries Exclusively**: Force all attack generation to invoke native penetration testing binaries (`ncrack`, `medusa`, `slowhttptest`, `hping3`, `scapy`, `iodine`, Metasploit).
3. **Dual-Engine Modular Architecture (`--engine auto|kali|python`)**: Provide modular attack generation backends with automated discovery and fallback safety.

## Decision
We adopt **Option 3: Dual-Engine Modular Architecture**.

The threat generator ([`src/traffic_gen/attack_flow.py`](../../src/traffic_gen/attack_flow.py)) and orchestrator ([`src/orchestrate.py`](../../src/orchestrate.py)) support three engine execution modes:
- `--engine kali`: Prioritizes native Kali Linux security tools (`ncrack`/`medusa`/`hydra` for SSH, `slowhttptest`/`hping3` for DoS, `scapy` for DNS and Botnet C2).
- `--engine python`: Uses pure Python standard library and lightweight PyPI dependencies (100% portable, zero system binary prerequisites).
- `--engine auto` *(Default)*: Dynamically discovers installed Kali binaries on system `PATH` and `~/traffic-env`, falling back cleanly to pure Python implementations if tools are absent.

## Comparative Analysis Matrix

| Dimension | Native Kali Security Binaries | Pure Python Standard Library / PyPI |
| :--- | :--- | :--- |
| **1. Adversary Realism** | **High**: Real protocol negotiations, banners, ciphers, and timing signatures generated by standard penetration testing toolchains. | **Synthetic**: Emulates protocol exchanges with simplified socket interactions. |
| **2. Feature Variance** | **High Entropy**: Realistic packet length variations, TCP window scaling, retransmissions, and flag distributions. | **Deterministic**: Predictable inter-arrival times (`piat_ms`), uniform packet sizes, and static payloads. |
| **3. Portability & Setup** | Requires Kali Linux OS, apt tool packages, and `root` / `CAP_NET_RAW` network privileges. | **Universal**: Runs on any OS with Python 3.9+ without external tool installation. |
| **4. Execution Overhead** | Spawns external C/C++ subprocesses; requires process watchdog and signal termination handlers. | **Minimal**: In-process or lightweight script with direct socket lifecycle management. |
| **5. Flow Throughput** | Capable of high volumetric rates (e.g. `hping3` kernel raw socket flooding). | Bounded by Python GIL and user-space socket loops (ideal for steady-state simulation). |

## Class-by-Class Tool Mapping

```
Threat Category              Kali Native Engine             Python Native Engine
────────────────────────────────────────────────────────────────────────────────────────
Class 3: SSH Brute Force     ncrack / medusa / hydra        Pure socket auth probe loop
Class 4: Slowloris DoS       slowhttptest / hping3          PyPI slowloris / partial HTTP headers
Class 2: DNS Exfiltration    scapy TXT/CNAME generator      Pure socket UDP DNS packer
Class 1: Botnet C2 Beacon    scapy / C2 stager beacon       Multi-round HTTP POST with jitter
Class 0: Benign Traffic      urllib.request / curl          urllib.request / curl
```

## Consequences & Label Integrity
- **Labeling Oracle Compliance**: All alternative tools target designated ports (`22` for SSH, `80/443` for DoS/Web, `53` for DNS, `8080/8888/9000` for Botnet) ensuring 100% compatibility with `assign_labels_vectorized()` in [`src/defender/client.py`](../../src/defender/client.py).
- **Process Safety**: Child process cleanup in `src/orchestrate.py` terminates `ncrack`, `medusa`, `hydra`, `slowhttptest`, and `hping3` to prevent orphan processes on VM 400.
