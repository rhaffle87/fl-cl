## 1. Model Details

### Overview
`CyberDefenseNet` is a lightweight, edge-deployable deep learning intrusion detection system designed to operate across distributed edge firewalls and hypervisor nodes (Proxmox VE cluster). It processes tabular flow metadata extracted from raw network packets via **NFStream** to detect encrypted cyberattacks without inspecting packet payloads.

### Model Architecture
The factory function `get_model()` provides three interchangeable backbones tailored to computational constraints:

1. **1D Convolutional Neural Network (`CyberDefenseCNN` - Default)**:
   - Feature extractor with 1D convolutions, batch normalization, LeakyReLU activations, and max-pooling.
   - Dynamically computed linear projection layer (`fc_input_dim`) evaluated via dummy forward pass.
   - Output classifier head mapping 32 tabular flow features to 5 traffic classes.
2. **Multi-Layer Perceptron (`CyberDefenseNet`)**:
   - 4-layer fully connected network with configurable hidden dimensions `[128, 64, 32]`, Dropout (0.2), and Batch Normalization.
3. **Transformer (`CyberDefenseTransformer`)**:
   - Token embedding projection with multi-head self-attention (`nn.TransformerEncoderLayer`) enforcing strict spatial integrity (`token_len * token_dim == input_dim`).

### Continual & Federated Learning Integration
- **Federated Orchestration**: Flower (`flwr`) gRPC framework supporting robust aggregation schemes (`FedAvg`, `FedMedian`, `Krum`, `TrimmedMean`).
- **Continual Learning**: Avalanche (`avalanche-lib`) with class-frequency weighted **Elastic Weight Consolidation (EWC)** and **Gradient Episodic Memory (GEM / A-GEM)** to eliminate catastrophic forgetting of historical traffic classes.

## 2. Intended Use

### Primary Intended Uses
- Real-time classification of encrypted network flows on edge gateway nodes.
- Incremental adaptation to zero-day and emerging cyber threats via continual learning without centralized raw packet retention.
- Collaborative multi-tenant defense across isolated subnetworks via privacy-preserving federated aggregation.

### Out-of-Scope & Unsupported Uses
- **Deep Packet Inspection (DPI)**: Payload content analysis or TLS decryption (the model strictly utilizes statistical flow metadata).
- **Non-IP Protocols**: Specialized non-Ethernet / proprietary industrial protocols not supported by NFStream.
- **Unsupervised Anomaly Detection**: The base architecture is a supervised multi-class discriminator; OOD detection is handled upstream via Mahalanobis/energy scoring.

## 3. Training & Evaluation Data

### Feature Representation (32 Tabular Flow Features)
Features are extracted in real time by NFStream from live network traffic on interface `ens19`:
- **Bidirectional Packet Counts**: `bidirectional_packets`, `src2dst_packets`, `dst2src_packets`
- **Byte Volumes**: `bidirectional_bytes`, `src2dst_bytes`, `dst2src_bytes`
- **Temporal Durations**: `bidirectional_duration_ms`, inter-arrival times (min, mean, std, max)
- **TCP Flag Frequencies**: SYN, ACK, FIN, RST, PSH count ratios
- **Payload & Header Statistics**: Min, mean, standard deviation, and maximum packet sizes

### Target Classes
| Class ID | Threat Class | Description & Attack Engine |
| :--- | :--- | :--- |
| **0** | **Normal** | Benign background HTTP/HTTPS requests generated by defender nodes |
| **1** | **Botnet** | Command & Control (C2) periodic beaconing patterns |
| **2** | **DNS Exfiltration** | High-entropy DNS TXT queries tunneling serialized data |
| **3** | **SSH Brute Force** | Rapid credential stuffing and connection attempts against port 22 |
| **4** | **DoS** | Slowloris low-and-slow HTTP exhaustion attack flows |

### Ephemeral Storage Policy
All training flow batches reside exclusively in RAMDisk storage (`/mnt/ramdisk/flows/`, `tmpfs`). No raw network packet flows are persisted to disk, guaranteeing privacy and regulatory compliance.

## 5. Security, Governance & Privacy Controls

1. **Differential Privacy (DP-SGD)**:
   - Configurable per-client gradient clipping (`--dp-max-grad-norm`) and Gaussian noise injection (`--dp-noise-multiplier`).
2. **Byzantine & Poisoning Robustness**:
   - Robust aggregators: `FedMedian`, `TrimmedMean` ($\beta=0.1$), and `Krum`.
   - Data Quality Gate: Jensen-Shannon Divergence (JSD) label distribution gate (default threshold $\le 0.60$) with auto-retraining trigger on drift ($\text{JSD} > 0.75$).
3. **Artifact Integrity & MLOps Governance**:
   - Weight Checkpoint Security: Enforced POSIX permissions `0600` (owner read/write only) on all `.pt` checkpoints.
   - Safe Deserialization: `torch.load(..., weights_only=True)` to prevent arbitrary code execution vulnerabilities.
   - Model Registry Aliasing: MLflow 3.x `champion`, `challenger`, and `previous_champion` aliases.
   - **1-Click Rollback**: Single-command instant recovery to previous champion via `python tools/validate_promotion.py --rollback`.

## 6. Export Formats & Edge Optimization

The pipeline automatically compiles and validates three optimized deployment formats per round:
1. **TorchScript JIT (`model_latest_scripted.pt`)**: C++ runtime ready, independent of Python runtime.
2. **Dynamic 8-Bit Quantization (`model_latest_scripted_quantized.pt`)**: Quantizes `nn.Linear` layers to `torch.qint8` reducing memory footprint by ~75% with <0.5% accuracy delta.
3. **Fisher-Guided Pruning (`model_latest_scripted_pruned.pt`)**: Aggregated Fisher Information Diagonals prune parameters with lowest task importance by fraction (e.g. 20%).

## 7. Limitations & Known Biases

- **Class Imbalance**: Normal and DoS classes naturally exhibit significantly higher flow volume than Botnet or SSH Brute Force. Addressed via static class weighting (`1.0, 250.0, 2.0, 5.0, 50.0`).
- **Feature Drift**: Abrupt topology changes or new benign protocol deployments may increase JSD drift score. Handled by drift snapshotting and automated 1-shot realignment retraining.
- **Hardware Profile**: Benchmarked on Proxmox VE KVM virtualization (x86_64, 4 vCPUs, 8GB RAM per node). Performance on ARM/embedded micro-controllers requires TorchScript C++ runtime compilation.
